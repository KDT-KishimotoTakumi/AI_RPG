# 確定世代不一致の復旧方針（承認済み）

2026-11-03、利用者が「この復旧案を採用する」を選択。T029bの復旧方針として採用する。
現行の同一世代修復・正常保存・ゲーム内容・Run/Profile形式は維持する。

- 本体とバックアップ計4ファイルから、形式・内部payloadが正常で同じ世代の周回/恒久ペアを探す。複数あれば最新の共通世代を候補にする。
- 同じ種別・同じ世代に異なる内容がある場合は推測で選ばず停止する。未対応形式/読込失敗も上書きしない。
- 世代が異なる周回と恒久データを混ぜない。片側だけの新しい変更は復旧結果に含めない。
- 候補の世代、現在より戻る可能性、失われる変更、元ファイルの保全を画面へ示し、取消/明示確定を提供する。
- 確定前に再読込し、候補が変われば停止して再確認する。元4ファイルと取引記録をCorruptへ保全できた後だけ、固定したペアを新しい取引世代で保存する。
- 保全/保存失敗中は進行停止し、確定済み内容のみ再試行する。
- 共通世代がなければ、全ファイルを保持して復旧不能を通知する。正常な側の削除/自動初期化は行わない。
- 本案の対象は整合するペアが残る場合。どの世代も推定できない場合の任意組合せ・巻戻し選択は追加しない。

検証済みの範囲（GS-061/062、証跡はdocs/VALIDATION.md）: 本体/バックアップ各組合せ、複数候補、衝突、未来版/読込失敗、取消、再読込変更、保全失敗、書込段階ごとの固定再試行、正常データ不変、UI損失通知、実ディスク/別プロセス再開。

有効な未完了取引は既存の再生を優先し、新しい経路から推測で置き換えない。新経路の予告は読取りのみ。保全は存在する原本を対象とし、不在ファイルを作成しない。
